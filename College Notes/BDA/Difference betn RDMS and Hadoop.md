| Feature        | RDBMS                                                                                                                                                                                                   | Hadoop                                                                                                                                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Architecture   | Centralized, row-column based. Data is stored in tables (relations) where rows represent records and columns represent attributes. Runs on a single physical machine or a tightly coupled server setup. | Distributed, file/block based. Data is split into blocks and stored across a cluster of machines using HDFS (Hadoop Distributed File System). Processing runs in parallel on the same nodes that store the data.     |
| Data types     | Structured only. Data must fit a predefined table format with defined columns, data types, and constraints. Examples: SQL tables, CSV with fixed schema.                                                | Structured, semi-structured, and unstructured. Can store CSV, JSON logs, raw text, images, video, and clickstream data without forcing them into a table format.                                                     |
| Schema         | Schema-on-write. You must define the table structure (columns, types, lengths, constraints) before inserting any data. Mismatched or extra fields are rejected immediately.                             | Schema-on-read. Data is stored as raw files first. The structure and parsing logic are applied later, at the time the data is read by a processing job (MapReduce or Spark).                                         |
| Processing     | SQL (Structured Query Language). Used to define, query, and manipulate data. Optimized for point queries and small, indexed lookups.                                                                    | MapReduce, Spark, Hive. MapReduce uses sort/merge to process entire datasets in batch. Spark adds in-memory processing for faster iterative workloads. Hive provides a SQL-like layer on top of Hadoop.              |
| Scalability    | Vertical (scale-up). When the machine runs out of capacity, you upgrade it with more RAM, CPU cores, or faster SSDs. Cost grows non-linearly, creating a financial ceiling.                             | Horizontal (scale-out). Add more standard machines to the cluster. Hadoop automatically detects new nodes, rebalances data blocks, and routes jobs to them without downtime or code changes.                         |
| Access pattern | Interactive, low-latency random reads and writes. Optimized for CRUD operations where you need to fetch or update a small number of records quickly using indexes (B-Trees).                            | Batch, write once and read many times. Optimized for high-throughput sequential scans of large datasets. Not designed for frequent random reads or small point lookups.                                              |
| Updates        | Frequent, granular record updates. You can run an UPDATE statement to change a single field in a single row in-place without touching the rest of the file.                                             | Append-only. HDFS files are immutable by design. You cannot edit bytes in the middle of a file. To correct a record, you append a new version or rewrite the entire partition using a distributed processing script. |
| Transactions   | ACID (Atomicity, Consistency, Isolation, Durability). Ensures transactions either fully succeed or fully fail, with strict consistency and no partial states.                                           | No ACID transactions in MapReduce. Follows a BASE model (Basically Available, Soft state, Eventual consistency). Data blocks may be temporarily inconsistent across replicas but eventually sync.                    |
| Data size      | Gigabytes to low terabytes. Performance degrades as data volume grows beyond this range due to disk seek time and single-machine limits.                                                                | Terabytes to hundreds of petabytes. Designed for massive-scale storage and processing across many nodes, where sequential streaming beats random seeks.                                                              |
| Hardware       | High-end enterprise servers and SAN storage. Requires specialized, expensive hardware with fast CPUs, large RAM, and premium storage arrays.                                                            | Low-cost commodity hardware. Pools the local storage and compute of standard, inexpensive servers over a network cluster. No need for premium hardware.                                                              |
| Cost           | Often licensed and expensive. Proprietary systems like Oracle or MS SQL charge per-core or per-server fees, plus high hardware costs.                                                                   | Free and open source. Apache Hadoop is open-source software, and it runs on cheap commodity hardware, keeping total cost low.                                                                                        |
| Best use       | OLTP, real-time transactions. Ideal for systems like banking ledgers, e-commerce carts, inventory management, and user profiles where sub-second lookups and strict consistency matter.                 | Big data, OLAP, batch analytics. Ideal for log aggregation, machine learning on large datasets, ETL pipelines, and exploratory analysis of raw text, images, or clickstreams.                                        |
